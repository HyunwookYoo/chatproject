# M6 Mailbox Devices and Own-Device Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 모든 내 기기가 받아들이고 보낸 kind 17 frame을 순서대로 기록하고, 내 기기끼리 연결될 때마다 서로 빠진 것을 가져와 처리해(양방향, 읽음 상태 포함) 폰이 꺼져 있던 동안 온 메시지가 알림과 대화창에 원래 순서로 한 번씩 들어오게 한다. 늘 켜 두는 내 기기(Windows 트레이, 선택한 Android)가 메일박스 역할을 하고, 보내지 못한 암호문을 넘겨받아 대신 재시도한다.

**Architecture:** 새 `chat_core::mailbox` 모듈이 kind 18 frame(내 기기끼리만)을 정의하고, `message/mailbox_store.rs`가 스키마 v3의 `mailbox_store`·cursor·인계 표를 다룬다. 기록은 M5의 seal/open/Commit/Welcome 트랜잭션 안에서 같은 커밋으로 쓴다. 가져온 항목은 새 actor 모듈 `account/manager/mailbox.rs`가 `seq` 순서로 기존 `receive_app`·`mls_request` 경로에 넣는다(송신 기기는 세션이 아니라 기록의 installation). 열지 못한 항목은 평문 기록으로, 읽음은 내 Read receipt 해석으로 맞춘다. 플랫폼 쪽은 Windows runner(C++)와 Android(Kotlin) method channel `chat_app/mailbox`, Dart는 설정·처음 연결 화면·알림 표시를 맡는다.

**Tech Stack:** Rust 1.92.0, 기존 openmls =0.9.0 / rusqlite =0.40.2 (SQLCipher 4.14), minicbor, sha2, iroh 1.3, FRB 2.11.1, UniFFI 0.32.2, Flutter 3.44.6, Win32(`Shell_NotifyIconW`, `PowerCreateRequest`/`PowerSetRequest`, `HKCU\...\Run`), Android `remoteMessaging` 포그라운드 서비스(minSdk 26).

**Spec:** [승인된 M6 설계](../specs/2026-11-06-m6-mailbox-design.md). 상위: [P2P 설계](../specs/2026-10-04-p2p-chat-design.md) 2.2·3·5.1·6.3·11절, [로드맵](2026-10-04-p2p-chat-roadmap.md) M6, [M5 설계](../specs/2026-11-01-m5-mls-1to1-design.md), [M5 결과](../results/2026-11-02-m5-mls-1to1.md) "관찰". 구현자는 spec과 이 계획을 모두 읽는다. 사용자는 2026-11-06 spec을 승인했다. **실행 방식과 이 계획의 검토는 아직 미확정이다.**

## Global Constraints

- 메일박스·동기화 상대는 **내 계정의 해제되지 않은 내 기기만**이다. kind 18은 `session.grant.peer == local.keys.peer_id()`이고 `grant_authorized`(`account/manager.rs:2605`)를 통과한 세션에서만 처리하고 보낸다. 그 밖의 세션에서 온 kind 18은 `MailboxReply::Refused`로 답하고 아무것도 읽거나 쓰지 않는다.
- 새 서버를 만들지 않는다. 새 네트워크 서비스·포트·ALPN 없음(기존 account ALPN `chatproject/account/1` 위의 새 frame kind 18).
- 기록 대상(spec 5.1): 받아들인 kind 17 App·Commit·Welcome·receipt, 이 기기가 보낸 kind 17 frame, 사본·동기화로 가져와 연 항목(원래 installation 그대로). **열지 못해 `DecryptFailed`(class 1–5)로 답한 frame과 평문 넘김으로만 저장한 메시지는 기록하지 않는다.** 같은 frame 해시는 한 번만.
- 보관: 해제되지 않은 내 다른 기기의 cursor가 모두 지나간 항목, 또는 기록 후 30일(`MAILBOX_RETENTION_MS = 2_592_000_000`)이 지난 항목을 지운다. 해제된 기기의 cursor는 바로 지운다. 새 기기 cursor는 처음 본 시점의 다음 `seq`. 저장 공간 상한 없음.
- 처리 순서: 상대 기기별로 `seq` 오름차순, 한 페이지를 다 저장한 뒤에만 그 기기의 `since_seq`를 올린다. 중복은 `processed_ct`가 거른다.
- 넘겨받은 항목의 복호 실패는 송신자에게 `DecryptFailed`로 답하지 않는다(답할 세션이 없다). 대신 평문 넘김을 요청한다. 평문 넘김으로 저장한 메시지에는 receipt를 보내지 않는다.
- 평문 기록은 내 기기끼리의 인증된 account 세션(InstallationCert + QUIC TLS) 안에서만 오간다. 로그·오류 detail·이벤트에 본문·키·암호문을 남기지 않는다(M5 규칙 유지).
- 송신 인계: 메일박스는 넘겨받은 암호문을 **그대로** 재시도한다(다시 봉인 금지). 백오프는 1초부터 두 배, 상한 `MAILBOX_MAX_DELAY_MS = 30_000`. 재암호화는 원래 기기만(M5 `REENCRYPT_CAP = 3` 그대로).
- 상대 쪽 `open_app`은 MLS 송신 leaf가 **세션 상대 계정의 현재(해제되지 않은) 기기**이면 받는다. 메시지 키·`processed_ct`의 installation은 송신 leaf의 것. M5 호환 분기·버전 구분 없음.
- 알림은 수신 처리(직접 수신 1건, 또는 한 동기화 묶음)가 끝난 뒤 대화별로 한 번 정한다. 이미 읽은 메시지(내 다른 기기에서 읽음 포함)와 내 계정이 보낸 메시지로는 알림을 띄우지 않는다.
- 평소 쓰는 Android 폰에 고정 알림이 생기지 않는다: 메일박스 모드 기본값은 Android `false`, Windows는 처음 연결 화면에서 `true`로 보여 준다. Android 부팅 자동 시작 없음(`RECEIVE_BOOT_COMPLETED` 금지).
- 기존 규칙 유지: 단일 storage writer, 메시지 하나 처리 = SQL 트랜잭션 하나(이제 `mailbox_store` 기록 포함), frame 상한 61,440 B(kind 18 inner ≤ 61,434 B), 기기 최대 5대.
- 버전 고정: Rust 1.92.0, FRB 2.11.1, UniFFI 0.32.2, 기존 pin 유지. 새 Rust crate 의존성 없음. `app/rust`의 `windows-sys =0.61.2`에 기능을 더할 필요가 생기면 기능 목록만 바꾸고 버전은 그대로. Flutter 새 패키지 없음(알림·트레이·서비스는 플랫폼 코드로).
- 플랫폼: 제품 대상은 Windows·Android(주)·iOS(메일박스 아님, 동기화는 함). Windows 네이티브 빌드(SQLCipher용 Strawberry Perl). Linux는 제품 대상이 아니지만 CI가 Linux에서 Rust·Flutter 시험을 돌리므로 Rust 시험은 플랫폼 중립이어야 한다.
- 시험 실행: `cargo +1.92.0 ... -j 6` 이하, 명령은 하나씩 순서대로(동시 실행 금지, 메모리 제한). CI 명령(`.github/workflows/ci.yml`): `cargo test --workspace --locked`, `cargo test --locked -p chat_core --features test-hooks`, `cargo test --locked -p chat_ffi --features test-hooks`, `cargo test --locked -p chat_node --features harness`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo clippy -p chat_core --features test-hooks --all-targets -- -D warnings`, `cargo clippy -p chat_ffi --features test-hooks --all-targets -- -D warnings`.
- 작업 root는 실행 시 `superpowers:using-git-worktrees`로 만든 격리 worktree(브랜치 `HyunwookYoo/m6-mailbox`). `git add .` 금지, 경로를 지정해 커밋한다. 커밋 메시지는 빈 줄 하나 뒤 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`로 끝난다. push·merge·서명·실기기 설치는 이 계획의 자동 범위가 아니다.

## Review Focus

1. **내 Read receipt가 그 메시지보다 먼저 도착하는 경우:** A3가 A1의 Read receipt를 A2에서, 그 메시지를 나중에 A1에서 가져오면 메시지는 읽음 상태로 저장되고 알림이 뜨지 않아야 한다. — Task 6의 `own_read_before_message_still_suppresses_notification`.
2. **페이지 처리 도중 앱이 죽는 경우:** 같은 페이지를 다시 받아도 메시지·알림이 두 번 생기지 않아야 한다. — Task 5의 `restart_mid_page_resumes_without_duplicates_or_second_notification`.
3. **해제된 기기의 세션이 아직 열려 있는 경우:** 해제가 반영된 순간부터 그 세션의 `SyncReq`·`PlainReq`·`Handoff`는 아무것도 받지 못해야 한다. — Task 7의 `revoked_device_open_session_gets_nothing`.
4. **원래 기기와 메일박스가 같은 암호문을 동시에 보내는 경우:** 상대는 한 번 저장하고 두 번째에도 `Ack`(재암호화 유발 없음), 원래 기기는 `전달됨` 한 번. — Task 8의 `same_ciphertext_via_origin_and_mailbox_acks_twice_stores_once`.
5. **30일 넘게 꺼져 있던(해제되지 않은) 기기가 돌아오는 경우:** 지워진 앞부분을 건너뛰고 남은 가장 오래된 항목부터 이어 받아야 하며 멈추거나 오류로 끝나지 않는다. — Task 4의 `cursor_behind_pruned_head_resumes_at_oldest_kept`.

## 2. 공통 계약

**스키마 v3** (`storage_meta.schema_version` = 3, `user_version` = 3). v2 표는 그대로, 다음을 더한다.

```sql
-- 이 기기의 기록 (spec 5.1). seq는 단조 증가, 재사용하지 않는다.
CREATE TABLE mailbox_store (
    seq INTEGER PRIMARY KEY AUTOINCREMENT,
    conversation BLOB NOT NULL CHECK(length(conversation)=32),
    sender_peer BLOB NOT NULL CHECK(length(sender_peer)=32),
    sender_install BLOB NOT NULL CHECK(length(sender_install)=32),  -- 원래 보낸 기기 (MLS leaf)
    kind INTEGER NOT NULL CHECK(kind IN (1,2,3)),  -- 1 kind 17 frame inner, 2 Delivered 노트, 3 HandoffStop 노트
    msg_id BLOB CHECK(msg_id IS NULL OR length(msg_id)=16),  -- App Text와 노트의 대상 메시지
    hash BLOB UNIQUE NOT NULL CHECK(length(hash)=32),  -- SHA-256(body)
    body BLOB NOT NULL CHECK(length(body) BETWEEN 1 AND 61434),
    recorded_at_ms INTEGER NOT NULL CHECK(recorded_at_ms>=0)
) STRICT;
CREATE INDEX mailbox_store_age ON mailbox_store(recorded_at_ms);

-- 내 다른 기기가 이 기기 기록을 어디까지 가져갔나 (보관 판정)
CREATE TABLE mailbox_cursor (
    installation BLOB PRIMARY KEY NOT NULL CHECK(length(installation)=32),
    next_seq INTEGER NOT NULL CHECK(next_seq>=1)
) STRICT;

-- 이 기기가 내 다른 기기 기록을 어디까지 처리했나
CREATE TABLE mailbox_pull (
    installation BLOB PRIMARY KEY NOT NULL CHECK(length(installation)=32),
    since_seq INTEGER NOT NULL CHECK(since_seq>=0)
) STRICT;

-- 메시지보다 먼저 온 상태 (Review Focus 1): 1 내가 읽음, 2 상대 전달, 3 상대 읽음
CREATE TABLE mailbox_status_ahead (
    conversation BLOB NOT NULL CHECK(length(conversation)=32),
    sender_peer BLOB NOT NULL CHECK(length(sender_peer)=32),
    msg_id BLOB NOT NULL CHECK(length(msg_id)=16),
    kind INTEGER NOT NULL CHECK(kind IN (1,2,3)),
    at_ms INTEGER NOT NULL CHECK(at_ms>=0),
    PRIMARY KEY(conversation,sender_peer,msg_id,kind)
) STRICT;

-- 메일박스가 넘겨받은 암호문 (spec 7)
CREATE TABLE mailbox_handoff (
    origin_install BLOB NOT NULL CHECK(length(origin_install)=32),
    conversation BLOB NOT NULL CHECK(length(conversation)=32),
    msg_id BLOB NOT NULL CHECK(length(msg_id)=16),
    peer BLOB NOT NULL CHECK(length(peer)=32),
    ciphertext BLOB NOT NULL CHECK(length(ciphertext) BETWEEN 1 AND 61434),
    attempts INTEGER NOT NULL CHECK(attempts BETWEEN 0 AND 4294967295),
    next_retry_at_ms INTEGER NOT NULL CHECK(next_retry_at_ms>=0),
    received_at_ms INTEGER NOT NULL CHECK(received_at_ms>=0),
    PRIMARY KEY(origin_install,conversation,msg_id)
) STRICT;

-- 이 기기의 메일박스 설정과 내 다른 기기가 알린 상태, 가동 기록
CREATE TABLE mailbox_local (
    singleton INTEGER PRIMARY KEY NOT NULL CHECK(singleton=1),
    enabled INTEGER NOT NULL CHECK(enabled IN (0,1)),
    first_link_shown INTEGER NOT NULL CHECK(first_link_shown IN (0,1))
) STRICT;
CREATE TABLE mailbox_device (
    installation BLOB PRIMARY KEY NOT NULL CHECK(length(installation)=32),
    mailbox INTEGER NOT NULL CHECK(mailbox IN (0,1)),
    announced_at_ms INTEGER NOT NULL CHECK(announced_at_ms>=0)
) STRICT;
CREATE TABLE mailbox_uptime (
    started_at_ms INTEGER PRIMARY KEY NOT NULL CHECK(started_at_ms>=0),
    ended_at_ms INTEGER NOT NULL CHECK(ended_at_ms>=started_at_ms)
) STRICT;
```

`mailbox_local`은 새 DB와 이관 모두 `(1, 0, 0)` 한 행으로 시작한다.

**v2→v3 이관 (`migration::upgrade_v2_to_v3`)**: `upgrade_v1_to_v2`(`storage/migration.rs:521`)와 같은 형태. 한 트랜잭션에서 `upgrade_v2_to_v3.sql`(위 표, `storage_meta`를 `CHECK(schema_version = 3)`로 다시 만들기, `mailbox_local` 행)을 실행하고 `user_version = 3`. 실패하면 v2 그대로. v1 DB는 v1→v2→v3를 차례로(각각 자기 트랜잭션). v3 DB를 v2 앱이 열면 기존 규칙대로 `StorageCorrupt`.

**frame kind 18** (`auth::envelope(18, inner)`, inner는 canonical CBOR `[1, op, ...]`, ≤ `MAX_INNER` 61,434 B, 디코딩 규칙은 `mls/wire.rs`와 같음):

| op | 요청 | 필드 | 응답 |
|---|---|---|---|
| 0 | `SyncReq` | since_seq | `SyncResp{entries, next_seq, more}` (op 8) |
| 1 | `Notify` | head_seq | `Ok` (op 9) |
| 2 | `PlainReq` | seq | `Plain(PlainRecord)` (op 10) 또는 `NoPlain` (op 11) |
| 3 | `Handoff` | entries: `[HandoffEntry]` | `Ok` 또는 `Busy` (op 12) |
| 4 | `Announce` | mailbox: bool | `Ok` |
| — | (내 기기가 아니거나 해제됨) | — | `Refused` (op 13) |

- `LogEntry { seq: u64, conversation: ConversationId, sender_peer: PeerId, sender_install: InstallationId, recorded_at_ms: u64, body: EntryBody }`, `EntryBody::{ Frame(Vec<u8>) /* kind 17 inner */, Delivered { msg_id: MessageId, receiver: InstallationId, at_ms: u64 }, HandoffStop { msg_id: MessageId, class: u8, epoch: u64 } }`. CBOR 태그 1/2/3 = 표의 `kind`.
- `SyncResp`는 항목을 `seq` 순서로, 인코딩이 `MAX_INNER` 안에 드는 만큼(최대 `PAGE_MAX_ENTRIES = 64`) 담고 항상 최소 1개를 담는다(최대 버킷 Text 항목 하나가 들어가야 한다 — Task 3 시험). `next_seq` = 마지막 항목 seq + 1(항목 없으면 요청 `since_seq`를 cursor 바닥으로 올린 값), `more` = 그 뒤에 항목이 더 있음.
- `PlainRecord { conversation, sender_peer, sender_install, msg_id, lamport: u64, prev_hash: [u8; 32], sent_at_ms: u64, kind: u8 /* 1 Text */, body: String /* ≤ 16,384 B */ }`.
- `HandoffEntry { conversation, peer: PeerId, msg_id: MessageId, ciphertext: Vec<u8> }`.
- `Refused`를 받은 쪽은 그 기기와의 동기화를 이번 세션 동안 멈춘다.

- 메일박스 기기의 30초 상한은 넘겨받은 행과 그 기기 자신의 outbox 재시도 모두에 적용한다(receipt 작업은 그대로 5분).
- Commit·Welcome 다이얼은 installation당 30초에 한 번까지.
- 알림 문구: 제목 = 연락처 별칭(없으면 "새 메시지"), 본문 = "새 메시지 N개", 미리보기 없음. Windows는 트레이 아이콘 풍선(`Shell_NotifyIconW` `NIF_INFO`), Android는 `NotificationManager` 채널 "메시지". 새 Flutter 패키지 없음.
- Android 알림 권한(API 33+)은 계정이 `Active`인 첫 실행에 한 번 묻는다(설계 8.6의 "복구 문구 확인 직후"와 기존 사용자 모두를 덮는다).
- Windows 전원 요청은 메일박스 ON이고 (AC 연결 또는 상태 알 수 없음 또는 배터리 없음)일 때 잡는다. 자동 시작은 `HKCU\...\Run` 값 `ChatProject` + `--tray`.
- 처음 연결 화면은 Windows에서 `first_link_shown`이 0이고 계정이 `Active`이면 한 번(새 연결, 업데이트 후 첫 실행, 이 PC에서 만든 계정 모두). 표시 여부는 core DB(`mailbox_local`)에 둔다(앱에 별도 설정 저장소가 없다).
- 앱 설정 화면이 없어서 `MailboxSettingsScreen`을 새로 만들고 계정 홈의 '내 기기' 옆 버튼으로 연다.
